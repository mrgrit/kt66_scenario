# kt66_scenario — 강사용 중앙 시나리오 서버

[kt66](https://github.com/mrgrit/kt66) 실습 랩에 **시나리오를 쏘고, 학생 대응을 채점하는**
강사용 중앙 서버다. kt66 본체와 분리되어 있다 — 강사 서버가 학생 랩 장애의 영향을
받으면 수업 운영이 함께 멈추기 때문이다.

```
강사 콘솔 ──▶ 발사 ──▶ [큐] ◀── 폴링 ── 학생 에이전트 ──▶ 학생 랩(envsim·injector)
                        │                      │
                        └──── 증거 요약 ◀───────┘
                                 ▼
                              채점(Ground Truth 대조)
```

## 왜 폴링인가

중앙은 **학생 랩에 접속하지 않는다.** 큐에 넣고 기다리고, 학생 에이전트가 물어보러 온다.

학생 서버는 각자의 망에 있고 NAT 뒤인 경우가 흔하다. 중앙에서 밀어 넣으려면 실습
환경마다 인바운드를 열어야 하는데, 그것은 강의 준비를 매번 방화벽 작업으로 만든다.
나가는 HTTP 하나만 되면 동작하는 쪽을 골랐다. 대가는 폴링 주기(기본 5초)만큼의
지연인데, 실습 시나리오에서 몇 초는 문제가 되지 않는다.

## 세 가지 시나리오 종류

| kind | 뜻 | 예 |
|---|---|---|
| `single` | 한 계통의 한 사건 (t+0 에 모여 있다) | `ENV-CRAC-01` 항온항습기 1대 정지 |
| `composite` | 서로 다른 계통이 동시에 — 원인이 하나로 안 보인다 | `PWR-ATS-01` 변전소 정지 + ATS 절체 실패 |
| `timeline` | 시간을 두고 벌어진다. **문제가 누적된다** | `TL-HEAT-01` 폭염에서 시작해 여유가 한 겹씩 벗겨진다 |

종류는 **단계 수가 아니라 성격**으로 가른다. 냉각탑 2대 동시 정지는 주입이 2건이지만
사건은 하나라 `single` 이다. 이것을 `composite` 로 부르면 학생에게 거짓말이 된다.

타임라인의 단계는 **시각이 되어야** 내려간다. 미리 다 주면 학생이 에이전트를 멈추는
것으로 시나리오를 통째로 회피할 수 있다. 시계는 중앙이 쥔다.

## Ground Truth 는 선택이 아니다

`ground_truth.root_cause` 와 `ground_truth.checks` 가 없으면 **로드를 거부한다.**
정답을 모르는 문제를 쏘면 학생은 시간을 버리고 강사는 채점을 못 한다.

카탈로그 오류는 서버를 죽이지 않고 목록으로 돌려준다 — 파일 하나가 깨졌다고 전체가
안 뜨면 수업 중에 손을 못 쓴다.

## 채점 — 기계가 본 것과 학생이 쓴 것을 섞지 않는다

이것이 이 서버의 핵심 설계다. 첫 검증에서 **학생이 아무것도 안 했는데 50/100 이
나갔다.** 에이전트가 자동 수집한 경보 텍스트에 `scope=2F/aisle-A` 가 들어 있어
"아일" 을 찾는 채점 항목이 통과해 버린 것이다.

그래서 채점의 모집단은 **학생이 제출한 증거뿐**이다(`source=student`).
에이전트가 수집한 경보·주입 결과는 맥락일 뿐 답안이 아니다 — 경보가 떴다는 사실은
학생의 성취가 아니다. 기계 관측까지 보려면 체크가 `include_machine: true` 를 명시해야 한다.

같은 이유로 SLA 의 탐지 시각도 학생의 최초 보고를 쓴다. 에이전트의 수집 시각을 쓰면
모든 학생의 탐지 시간이 0 이 되어 SLA 가 무의미해진다.

### check 유형

| 유형 | 판정 |
|---|---|
| `alarm_seen` | 학생이 그 경보를 **인지해 보고**했는가 (경보가 떴는가가 아니다) |
| `keyword` | 학생 서술에 근거 표현이 있는가 (`any:` 로 여러 표현 허용) |
| `evidence_kind` | 해당 종류(`action` 등)의 증거가 있는가 |
| `order` | 두 행위의 선후가 맞는가 (예: SIEM 을 학습 job 보다 먼저 끄지 않았는가) |
| `no_evidence` | 이런 서술이 **없어야** 통과 |
| `check_id` | 에이전트가 그 항목을 직접 통과로 보고했는가 |

원칙 셋:
1. **정답 하나를 강요하지 않는다.** 시설 장애 대응에 유일해는 없다. "무엇을 했는가"보다
   "근거를 남겼는가"를 본다.
2. **부분 점수를 준다.** 전부 아니면 0 인 채점은 학생이 어디서 갈렸는지 알려 주지 못한다.
3. **금지 행위는 감점이 아니라 표시다.** `forbidden_hit` 로 남겨 강사가 그 항목만 따로 본다.

## 설치

### 강사 서버

```bash
git clone https://github.com/mrgrit/kt66_scenario.git
cd kt66_scenario
INSTRUCTOR_KEY=원하는키 PORT=8040 docker compose up -d --build
# 콘솔: http://강사서버:8040/
```

`scenarios/` 와 `data/` 는 이미지 밖의 볼륨이다. 수업 중에 시나리오를 고치고
`콘솔 → 재적재`(또는 `POST /api/reload`)로 반영할 수 있고, 백업은 `cp -r data` 한 번이다.

### 학생 랩 (kt66 호스트마다 1개)

```bash
# 상주 실행 — 폴링하며 주입을 받고 경보를 수집한다
python3 agent/kt66_scenario_agent.py \
  --server http://강사서버:8040 --name "홍길동" --cohort A \
  --envsim http://127.0.0.1:8010 --injector http://127.0.0.1:8030
```

최초 실행에서 토큰을 받아 `~/.kt66s_agent.json`(0600)에 저장한다. 이후는 인자 없이 실행된다.
토큰이 신원이므로 재설치해도 이력이 이어지고, 남의 토큰을 추측해 발사를 가로챌 수 없다.

학생이 대응을 기록하는 방법:

```bash
A="python3 agent/kt66_scenario_agent.py"
$A --report "CRAC_DOWN 확인 — 항온항습기 A 정지" --kind alarm
$A --report "냉동기·펌프·냉각탑 정상. crac-01 단독 고장이다" --kind observation
$A --report "시설 담당 통보, 예비 공조 검토 요청" --kind action
$A --submit          # 제출하면 즉시 채점 결과가 나온다
```

## 강사 조작

| 하는 일 | 콘솔 | API |
|---|---|---|
| 전체 발사 | 발사 탭 → 전체 학생 | `POST /api/launch {"audience":"all"}` |
| 분반 발사 | 발사 탭 → 분반 | `{"audience":"cohort:A"}` |
| 특정 학생 | 학생 탭에서 체크 → 발사 | `{"audience":"students:3,7"}` |
| 자동 발사 | 자동 발사 탭 | `POST /api/schedule` |
| 강제 채점 | 진행 탭 → 채점 | `POST /api/grade/{launch_id}` |
| 증거 열람 | 진행 탭 → 증거 | `GET /api/evidence/{launch_id}` |

자동 발사는 간격마다 목록의 시나리오를 순서대로(또는 무작위로) 쏜다. 스케줄러 루프는
예외를 삼키고 계속 돈다 — 수업 중에 조용히 멈추는 것이 최악이기 때문이다.

## 검증 기록

카탈로그의 모든 시나리오는 실제 kt66 envsim 에 주입해 확인한 뒤 `verified: true` 를 붙였다.
각 파일 상단 주석에 실측값이 남아 있다. 예: `ENV-CT-01` 은 축열 소진까지 20분,
이후 `TEMP_WARN(27°C) → TEMP_CRIT(32°C) → TEMP_SHUTDOWN(38°C)` 로 전개된다.

파이프라인 자체도 종단 간 확인했다: 발사 → 폴링 → 실제 주입 → 경보 발생 →
증거 수집 → 채점. 무대응 0/100, 정상 대응 100/100.

## 라이선스 · 관계

kt66 실습 과정의 부속 도구다. 시나리오 스키마는 tw2 `battle-scenarios` 의
`verify` 구조를 이어받았다.
